# 实验室代码复用规则

- 后续研究只推进 SR 与局部／全局固定 1:1 通道分工；PN、OC、蒸馏等旧方向停止新增实验。
- 训练统一使用 `scripts/train.py → src/runner.py → src/trainer.py`；数据统一使用 `src/data.py`；最终报告使用 `src/evaluator.py` 与 `src/metrics.py`。新模型只接入 `src/models/<name>/adapter.py` 的标准接口。
- 不另写训练循环、数据加载器、数据划分、增强、优化器、选模或指标函数来替代已有实现。确有接口缺口时先说明缺口，做最小接口修改；不得借机更换训练协议。
- 默认标准以 `configs/train.json` 和上述原代码为准：Houston2013 官方划分、PCA30、11×11、100轮、batch128、AdamW lr=1e-4、weight_decay=0.01；2026-11-02用户更新：后续所有实验至少使用seed6、7、8，不再默认单seed6。组别与其他设置仍按审核矩阵执行，不自动新增模型、组合或更多种子。
- 原训练器目前按既定轮次的测试 OA 保存模型。如需改变这项规则，必须单独提出并获用户同意；不可将其结果描述为独立测试，也不可自行切回验证选模。
- 不重跑 paper_20261028 的27项；历史结果原样保留。旧验证流程结果只能作为历史依据，不与实验室原流程结果混合计算增益。
- 新实验先给出组别、变量、设置、数量供用户审核。用户已于2026-10-29明确批准当前9组、种子6／7／8的SR原流程方案开始训练；按该方案执行，不额外扩展实验。
- `docs/archive/` 只读追溯；不要从中恢复旧训练器作为日常入口。旧模型类路径保留用于加载整模型 checkpoint。
- 数据与运行产物分别留在 `data/`、`model/`、`log/`、`report/`、`pic/`，不混入源码或提交大文件。每次实验名称包含批次、组别、种子，禁止覆盖旧结果。
- 对话与 Markdown 行内公式用代码反引号或普通文本，不使用单个美元符号包裹公式。
