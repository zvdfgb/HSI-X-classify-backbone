# 本轮实验执行规范与代码复用

本轮以已审核的9组方案为范围。用户要求尽量复用实验室backbone并保持比较标准一致，因此采用现有模型适配器体系，复用上一轮已经运行过的三种子验证实验循环。

## 1 已核对的实验室调用链

常规实验：`scripts/train.py → ExperimentRunner → ConfigManager → src.trainer.myTrain/train → getMyData → model_registry → model/adapter → evaluator/metrics`。

上一轮三种子验证实验：`scripts/train_transmixer_fusion.py → src.fusion_experiment.execute → prepare_data/run_one/evaluate/benchmark`。它已实现固定验证划分和验证选模；这与早期 `trainer.py` 用测试集选检查点的流程不同。

本轮明确延续后一套规范。它对应基准目录 `report/fusion_ablation/fusion_20261024_210925_749584`，不是把不同协议的旧成绩放在同一张表里。

## 2 复用位置与新增范围

| 职责 | 本轮处理 |
| --- | --- |
| 基础网络 | 直接继承 `src/models/transmixer_net/model.py`；原文件保持不变 |
| SSM和1∶1模块 | 完全调用原实现，不复制模块，不改扫描顺序 |
| 新模型 | 放在 `src/models/transmixer_paper/model.py`，改变汇总或分类支路；纠偏使用hook读取原网络中间结果 |

原 `scripts/train.py`、`src/trainer.py`、`src/data.py`、`src/evaluator.py`、`src/metrics.py` 保持原行为。新模型也能通过ConfigManager与原生adapter接口构建，合成数据测试包含保存及重载。

## 3 逐项锁定的标准

共享参数不从新配置随意覆盖，而直接读取封存的旧批次配置：Houston2013；种子6/7/8；100轮；batch128；PCA30；11×11；AdamW；lr0.0001；weight decay0.01；验证比例20%；划分与PCA种子20261024；4个CPU线程；num_workers0；不丢最后一批。

保留严格确定性、数学版attention、禁用TF32、禁用cuDNN benchmark。验证每轮执行，先比验证OA，平手比较验证分类CE。

唯一预先设计的训练预算差别是PN1/PN2：相同G0检查点上分别训练50轮纠偏器，基础参数、BN统计及Dropout均固定。概念路线按审核稿额外使用0.1倍辅助MSE；这些是待测方法本身的变化。

筛选及训练阶段不推理测试集。所有固定配置完成后，统一对9组进行一次最终测试，保存逐样本预测，不根据测试成绩改参数、删组或重选种子。

## 4 基线复用必须通过的核验

1. Torch、NumPy、CUDA版本与旧运行记录一致。
2. 原基础网络、既有融合模型和适配器源码哈希一致。
3. 输入mat文件哈希、PCA solver、各类样本数、训练／验证／测试位置数组一致。
4. 旧100轮日志完整；检查点确实由验证集选出。
5. 在当前输入处理上重现每个种子的所有验证预测，并复现验证分类CE，容差1e-6。
6. 在真实数据上重跑基线第一轮，与旧第一轮的训练损失、验证损失及混淆矩阵比较，检查默认训练行为没有漂移。

任何一项失败都会停止，不会换环境、换划分或自动降成CPU继续运行。正式批次保存配置、源码快照、来源哈希、数据清单、检查点哈希和实时状态。
