# TransMixer 双模态交互实验

## Goal

在现有固定 1:1 TransMixer 上实现可复现的 7 组融合对照，完成代码验证和本机短程试跑，提供正式多种子训练入口与中文解读。未观察结果前不认定哪种交互最好。

## Problem Statement

当前 HSI 分支有 SSM、全局注意力和局部卷积，辅助模态只有浅卷积；两模态通过拼接和 1×1 卷积融合。需要区分交互方向、额外容量、全局/局部分工的作用。

## Context From Memory

历史记录与当前报告提示：B1–B4 单种子结果没有稳定提升证据，应采用小范围受控消融。历史训练器按测试集选模型；本批采用独立验证协议，不能直接与旧数字比较。默认项目知识库不存在；以已核对的源码、报告与历史索引为依据。

## In Scope

| 组 | 操作 | 问题 |
|---|---|---|
| F0 | 原始拼接，无新增交互 | 新协议基线 |
| F1 | 仅辅助特征自注意力增强 | 增加表达能力是否已经足够 |
| F2 | 辅助特征指导 HSI | 这个方向是否有用 |
| F3 | HSI 指导辅助特征 | 相反方向是否有用 |
| F4 | 共享参数的双向全特征交叉注意力 | 双向是否优于单向 |
| F5 | HSI 全局流用跨模态注意力、局部流用局部交互，双向更新 | 与现有分工结合是否有效 |
| F6 | 将 F5 的两类交互算子对调 | 分工匹配是否有独立贡献 |

所有交互位于最后一个 TransMixer 块的两流输出后、流融合投影前。F0 与旧 B0 数学一致。F1–F4 使用同一种共享注意力消息模块；F4 多一次调用，计算量不相同。F5/F6 具有完全相同参数与初始化，仅分配算子不同。辅助特征先投影为两组再参与运算，不声称原始辅助通道天然具有全局/局部语义。

## Out Of Scope

不改旧模型或旧训练脚本的行为，不叠加教师、原型、超图或小波，不使用历史 checkpoint 作为新协议结果，不修改数据原文件，不发送通知邮件。

## Constraints

- 使用独立新模型目录、独立实验脚本与唯一输出目录；通过注册表提供统一适配器。
- 相同种子下共享的 B0 参数完全一致；新增模块初始化不改变外部随机数状态。
- CUDA使用严格确定性模式与SDP数学后端，关闭内存优化/Flash SDP和TF32；不允许仅警告后继续。首次试跑遇到非确定性警告，已中止且单独归档，不并入整批结果。
- 残差交互强度从零开始；单元测试验证零强度退化为 B0，非零时方向性和梯度有效。
- 保留原有反射补边、配对随机翻转、PCA30、窗口11、AdamW 与学习率 1e-4 等主要设置；drop_last=False 避免丢弃样本。
- 全场景无标签 PCA/标准化，明确为传导式预处理；固定预处理种子，不将其称为归纳式评估。
- 从官方训练中心按类别分层划出20%验证样本，划分种子20261024；所有模型及训练种子共用该划分。验证与训练图像块可能有空间重叠，明确为同场景协议。
- 只用验证OA选 checkpoint（同分用较低验证损失）；短程阶段不推理测试集；正式阶段选模后只评估对应 checkpoint 一次。
- 保存全部配置、位置索引、类别计数、源文件哈希、训练曲线、逐类指标、参数量、实测时延、显存、交互强度、状态和错误；禁止旧文件冒充新结果。

## Assumptions

本机只发现 Houston2013 数据，先在该数据上跑完整7组短程试验；Berlin 的配置和缺文件诊断一并准备。短程采用10 epochs、seed6；正式配置100 epochs、seeds6/7/8。训练预算在观察准确率前固定。短程排序不是最终结论。

## Blocking Questions

无。用户已授权设计并实践本地实验。

## Acceptance Criteria

- 7个模型均可构建、前向及反向；支持1通道LiDAR与4通道SAR、训练/评估模式，输出有限 logits。
- F0/零强度交互与B0输出一致；共享权重一致；F5/F6同参数预算；交互方向按设计生效。
- 固定划分可复现、三组中心无交集、各类训练/验证均非空；缺文件、配置错误、重复输出在训练前失败。
- 实际完成7组10轮试跑，验证选模有日志与指标。若运行被用户或外部失败中断，保留失败状态，不声称完成。
- 形成一键脚本、正式配置和中文报告，区分实测、代码已实现及待验证结论。

## Edge Cases

CUDA缺失不得静默改CPU；空类别、重复中心、越界位置、无标签中心、偶数窗口、非法种子或模式均报错。中断/异常记录当前状态。只在新输出路径保存 state_dict。批次正式训练不自动据短程测试成绩筛模型。

## Validation Plan

运行新模型与协议的单元测试，复跑已有B1–B4测试，执行CLI dry-run和缺文件检查，然后执行GPU短程配置。确认生成结果为验证集且测试评估关闭，检查每轮样本数、损失与梯度有限。

## Execution Plan

1. 实现模型、注册适配器和对照测试。
2. 实现轻量数据接口、固定划分、验证选模和输出记录；只加载实际使用的PCA特征和辅助模态。
3. 验证后跑7组短程实验，记录实测成本。
4. 生成中文报告与正式运行说明。

## Open Questions

正式多种子实验是否支持收益，以及SAR场景能否复现，留待对应实验，不作为本轮先验结论。

## Self-Check

Ready for implementation。无阻塞问题；数据/模型旧行为隔离；初筛与确认阶段明确；允许实现与本地有限试跑。
